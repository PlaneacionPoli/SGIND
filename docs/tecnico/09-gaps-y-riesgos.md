# Gaps y riesgos (con evidencia)

## Crítico

| ID | Gap | Evidencia | Riesgo |
|---|---|---|---|
| G-01 | El pipeline que produce los datos de indicadores (`scripts/`, ~130 archivos incluyendo 23 módulos en `scripts/etl/`) no está integrado al backend ni automatizado | `backend/app` no tiene ningún `subprocess`/llamada hacia `scripts/*.py`; `.github/workflows/` no ejecuta el pipeline; `config/settings.toml [schedule]` está declarado sin implementación | Si nadie ejecuta el pipeline manualmente, los indicadores se congelan sin ningún error visible para el usuario |
| G-02 | ~~Entorno de pruebas del backend roto~~ **Corregido en Oleada 0 — era un falso negativo.** `backend/.venv312` (Python 3.12.10 + SQLAlchemy 2.0.36) ya existía y funciona; el fallo original se debía a correr con el Python 3.14 global en vez de este venv, documentado en `backend/README.md` desde antes de esta auditoría | Con el venv correcto: `SGIND_DATA_PATH=../data PYTHONPATH=. backend/.venv312/Scripts/python.exe -m pytest tests/ -q` → 123 passed, 16 skipped, 36 failed reales (triados en `08-testing.md`) | Ya no bloquea nada; riesgo remanente bajo — reforzar en onboarding/CI que se use `.venv312` |
| G-03 | ~~Semaforización de cumplimiento duplicada~~ **Corregido en Oleada 2 (2026-09-20).** Eran en realidad 6 implementaciones divergentes en backend (`procesos_builders.py`, `cmi_builders.py` x3, `resumen_builders.py::_retos_category`, `om_builders.py::CATEGORIA_COLORS`) + 3 copias de paleta en frontend (`cmiChartColors.ts`, `CmiVistaRapidaCards.tsx`, `CmiProcesosResumenTab.tsx`) — todas ahora delegan a `categorizar_cumplimiento`/`COLOR_CATEGORIA` (backend) y `design-tokens.ts::SEMAFORO` (frontend, fuente única confirmada). Se agregó parámetro `regimen` explícito a `categorizar_cumplimiento` para que Retos y Proyectos usen el régimen Plan Anual incondicionalmente por tipo (no por lista de Id) — confirmado con negocio | `domain/categorization.py`, `domain/constants.py`, `domain/procesos_builders.py`, `domain/cmi_builders.py`, `domain/resumen_builders.py`, `domain/om_builders.py`, `frontend/src/lib/design-tokens.ts`, `frontend/src/components/cmi/{cmiChartColors.ts,nivelUtils.tsx,CmiVistaRapidaCards.tsx,CmiProcesosResumenTab.tsx}` | Antes: el mismo indicador podía mostrarse con distinto color/estado según la pantalla, especialmente en regímenes especiales |
